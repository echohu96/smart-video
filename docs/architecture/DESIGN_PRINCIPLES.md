# 设计原则

## 核心设计理念

### 🎯 只保存总结，不保存视频

**核心原则**：Smart Video 的目标是生成和保存视频内容的总结，而不是保存视频文件本身。

### ✅ 设计要点

1. **只下载字幕文件**
   - 字幕文件体积小（通常 < 100KB）
   - 包含视频的完整文本内容
   - 下载速度快

2. **不下载视频文件**
   - 视频文件体积大（通常几百MB到几GB）
   - 用户可以在 YouTube 上直接观看原视频
   - 节省大量存储空间

3. **保存视频 URL**
   - 在生成的 Markdown 总结中保存视频 URL
   - 方便用户随时查看原视频
   - 作为总结的引用来源

4. **临时音频处理（仅无字幕时）**
   - 如果视频没有字幕，临时下载音频用于转录
   - 使用 Whisper 进行语音识别
   - **转录完成后立即删除音频文件**

## 工作流程

```
YouTube URL
    ↓
下载字幕文件（不下载视频）
    ↓
解析字幕 → 提取文本
    ↓
AI 分析总结
    ↓
生成 Markdown（包含视频 URL）
    ↓
保存总结文件
```

### 无字幕视频的特殊处理

```
YouTube URL（无字幕）
    ↓
临时下载音频文件
    ↓
Whisper 转录
    ↓
立即删除音频文件 ← 关键：不保存
    ↓
AI 分析总结
    ↓
生成 Markdown（包含视频 URL）
    ↓
保存总结文件
```

## 存储空间对比

| 内容类型 | 体积 | 是否保存 |
|---------|------|---------|
| 视频文件 | 100MB - 几GB | ❌ 不保存 |
| 音频文件（临时） | 10-50MB | ❌ 转录后删除 |
| 字幕文件 | < 100KB | ✅ 可选缓存 |
| Markdown 总结 | < 50KB | ✅ 保存 |

**结论**：只保存总结文件，存储需求极小。

## 优势

1. **节省存储空间**
   - 一个视频总结通常 < 50KB
   - 1000 个视频总结 ≈ 50MB
   - 而 1000 个视频文件可能 > 100GB

2. **快速处理**
   - 字幕下载速度快（几秒）
   - 不需要等待大文件下载

3. **易于管理**
   - 总结文件可以轻松备份
   - 可以版本控制（Git）
   - 可以搜索和索引

4. **灵活性**
   - 用户可以在 YouTube 上观看原视频
   - 总结作为学习笔记和参考

## 实现细节

### yt-dlp 配置

```python
ydl_opts = {
    'skip_download': True,  # 关键：跳过视频下载
    'writesubtitles': True,  # 只下载字幕
    'writeautomaticsub': True,
    # ...
}
```

### 文件管理

- `output/summaries/` - 保存 Markdown 总结文件
- `cache/subtitles/` - 可选：字幕缓存（可删除）
- `cache/temp/` - 临时文件（自动清理）

### Markdown 模板

总结文件包含：
- 视频标题、作者、时长
- **视频 URL**（重要）
- AI 生成的总结内容

## 未来扩展

即使未来添加 Web 界面或定时任务，核心原则不变：
- 不保存视频文件
- 只保存总结和 URL
- 用户通过 URL 访问原视频
